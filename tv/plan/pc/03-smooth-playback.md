# P3 — ניגון חלק בלי תקיעות

[← חזרה לתוכנית](../../plan.md)

## מטרה
שסרטים יתנגנו בלי עצירות ובלי "טוען…". העיקרון: **הטלוויזיה מנגנת את הקובץ המקורי (Direct Play), ברשת מהירה ויציבה.**
רוב התקיעות נובעות מהרשת או מפורמט לא מתאים — לא מהאפליקציה.

המשימה כוללת: מדריך למשתמש (רשת, פורמטים, מחשב), כלי המרה מראש לקבצים בעייתיים, וכלי אבחון בשרת ובאפליקציה.

---

## 1. רשת

### כמה מהירות צריך
| סוג קובץ | גודל טיפוסי | קצב (bitrate) | מהירות רשת מומלצת |
|---|---|---|---|
| 720p / 1080p דחוס | 1–4GB | 3–8 Mbps | 15 Mbps |
| 1080p BluRay | 8–15GB | 15–30 Mbps | 50 Mbps |
| 4K | 15–30GB | 25–50 Mbps | 100 Mbps |
| 4K Remux | 40–80GB | 50–100+ Mbps (קפיצות) | 150 Mbps+ |

**חישוב מהיר:** קצב ממוצע (Mbps) ≈ גודל הקובץ ב-GB × 8000 ÷ אורך בשניות. השרת יחשב ויציג את זה לכל קובץ (ראו סעיף 5).

### המלצות, לפי סדר חשיבות
1. **המחשב מחובר לראוטר בכבל.** חובה.
2. **הטלוויזיה בכבל** אם אפשר. אם הראוטר רחוק — מתאמי רשת דרך החשמל (Powerline, למשל AV1000 ומעלה) או נקודת Mesh עם יציאת כבל.
3. **אם Wi-Fi — רשת 5GHz** (לא 2.4GHz), ראוטר בקו ראייה או בחדר סמוך.
4. **מלכודת 100Mbps:** בהרבה טלוויזיות יציאת הכבל היא Fast Ethernet (100Mbps). מספיק לכל 1080p ולרוב ה-4K, אבל לא ל-4K Remux. במקרה כזה Wi-Fi 5GHz טוב יכול להיות מהיר יותר — כדאי למדוד את שניהם.
5. להימנע מהורדות כבדות (טורנטים, עדכוני Windows) במחשב בזמן צפייה.

### איך מודדים
- בדיקת מהירות **מהמחשב לטלוויזיה** (לא מהירות האינטרנט!): השרת יגיש קובץ בדיקה, והאפליקציה תמדוד (ראו סעיף 6).
- התוצאה מוצגת כ: "הרשת שלך מתאימה ל: 1080p ✓ / 4K ✓ / 4K Remux ✗".

## 2. פורמטים — Direct Play

| | וידאו | שמע | מכולה (container) |
|---|---|---|---|
| **מומלץ** | H.264, H.265 (HEVC) | AAC, AC3, E-AC3 | MKV, MP4 |
| **תלוי מכשיר** | AV1, VP9, HDR10+/Dolby Vision | DTS, DTS-HD, TrueHD | — |
| **בעייתי** | XviD/DivX, MPEG-2, WMV | — | AVI, WMV |

### אם הקול בעייתי (DTS / TrueHD) — המרה של השמע בלבד
מהיר (שניות עד דקות), בלי לפגוע בתמונה:
```
ffmpeg -i movie.mkv -map 0 -c copy -c:a ac3 -b:a 640k movie-fixed.mkv
```

### אם הקובץ כולו בעייתי (AVI ישן וכו') — המרה מלאה
איטי (בערך זמן הסרט או יותר), תוצאה טובה:
```
ffmpeg -i movie.avi -c:v libx264 -crf 20 -preset medium -c:a aac -b:a 192k movie.mp4
```

### כלי המרה מראש (חלק מהמשימה)
- סקריפט `convert-problem-files.bat` בתיקיית השרת:
  - עובר על רשימת הקבצים הבעייתיים שהשרת זיהה.
  - ממיר רק את מה שצריך (שמע בלבד / מלא).
  - שומר את המקורי בצד (`_original\`) עד שהמשתמש מוחק ידנית.
  - רץ בלילה / ברקע, עם התקדמות בחלון.
- דורש ffmpeg מותקן.

### אלטרנטיבה בצד הטלוויזיה (לבחינה)
הוספת **מפענח השמע של FFmpeg** לנגן (Media3 FFmpeg extension) — מאפשר DTS/TrueHD בכל טלוויזיה, בלי המרה.
מגדיל את ה-APK ודורש בנייה של הרחבה. נחליט לפי כמה קבצים כאלה יש בספרייה.

### מה **לא** עושים: המרה בזמן אמת בשרת (Transcoding)
מעמיס מאוד על המחשב, פוגע באיכות, ומסבך את השרת. מחוץ לתוכנית.

## 3. המכשיר שמנגן
- המעבד וה-Wi-Fi המובנים בהרבה טלוויזיות חלשים.
- אם יש תקיעות גם אחרי סידור הרשת — מכשיר סטרימינג חיצוני:

| מכשיר | הערות |
|---|---|
| Google TV Streamer | חדש, יציאת כבל רשת מובנית |
| Chromecast with Google TV | זול; לכבל צריך מתאם USB-C עם Ethernet |
| Nvidia Shield TV | הכי חזק; מנגן כמעט הכל כולל DTS/TrueHD; כבל רשת 1Gbps |

האפליקציה תעבוד על כולם.

---

## 4. המחשב
- **מצב שינה:** כבוי בזמן חיבור לחשמל, והשרת מונע שינה בזמן שידור ([P2](02-install-run.md#שינה-וחיסכון-בחשמל)).
- **דיסקים חיצוניים / HDD:** לבטל כיבוי דיסק אוטומטי (אפשרויות צריכת חשמל ← "כבה דיסק קשיח אחרי: אף פעם"). אחרת — עצירה של כמה שניות בתחילת סרט.
- **USB:** דיסק חיצוני ביציאת USB 3 (כחולה), לא USB 2.
- **אנטי-וירוס:** אם יש האטה, להחריג את תיקיות הסרטים מסריקה בזמן אמת.
- המחשב **לא** צריך להיות חזק — הוא רק שולח קבצים.

---

## 5. בצד השרת
- **ניתוח כל קובץ בסריקה** (עם ffprobe, אם מותקן): קודק וידאו, קודק שמע, רזולוציה, HDR, קצב ממוצע.
- **סיווג:** "יתנגן" / "אולי" (DTS, AV1, HDR) / "בעייתי" (AVI, XviD) — נשלח לאפליקציה כ-`playable` ([S5](../server/05-api.md)).
- **דף הסטטוס:** רשימת קבצים בעייתיים + מה צריך לעשות לכל אחד + כמה קבצים בקצב גבוה מדי לרשת שנמדדה.
- **שידור יעיל:** קריאה בגושים גדולים (1MB), בלי דחיסה (וידאו לא נדחס), תמיכה בכמה בקשות Range במקביל.
- **נקודת קצה לבדיקת מהירות:** `GET /api/speedtest?mb=50` — מחזיר 50MB של נתונים אקראיים מהזיכרון.

## 6. בצד האפליקציה

### הגדרות הנגן
- **באפר:** מינימום 30 שניות, מקסימום 120 שניות, התחלה אחרי 2.5 שניות; בקובץ בקצב גבוה — מחכים ליותר לפני התחלה.
- **ניסיון חוזר אוטומטי** בניתוק רגעי (3 ניסיונות) לפני הודעת שגיאה.
- **Tunneling** (מצב ניגון ישיר בחומרה) — יופעל במכשירים שתומכים, משפר חלקות ב-4K.
- **התאמת קצב רענון** (Frame rate matching) — הטלוויזיה עוברת ל-24Hz לסרטים, מונע "קפיצות" בתנועה. לפי תמיכת המכשיר.

### מסך מידע בנגן ("מה קורה עכשיו")
נפתח בכפתור בפקדים (או לחיצה ארוכה למעלה):
```
┌─────────────────────────────── מידע ניגון ───┐
│ קובץ:      MKV · H.265 1080p · AC3 5.1        │
│ קצב קובץ:  ממוצע 18 Mbps                      │
│ רשת:       42 Mbps (נמדד עכשיו)               │
│ באפר:      ████████░░  48 שניות               │
│ פריימים שנפלו: 0                              │
│ מצב: ✓ הרשת מספיקה לקובץ הזה                  │
└──────────────────────────────────────────────┘
```
- **אבחון אוטומטי** בשורה האחרונה:
  - "הרשת איטית מהקובץ — נסה כבל רשת או Wi-Fi 5GHz".
  - "המכשיר מתקשה לפענח (פריימים נופלים) — הקובץ כבד מדי למכשיר".
  - "השמע לא נתמך — בחר רצועת שמע אחרת או המר את הקובץ".

### בדיקת רשת מההגדרות
"בדוק מהירות למחשב" ← הורדה מ-`/api/speedtest` ← "הרשת שלך מתאימה ל: 1080p ✓ / 4K ✓ / 4K Remux ✗".

### אזהרה מראש
בעמוד סרט: אם קצב הקובץ גבוה מהמהירות שנמדדה לאחרונה — "הקובץ הזה כבד לרשת שלך, ייתכנו עצירות".
